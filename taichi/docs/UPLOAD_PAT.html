01 · ONE COMMAND

先解壓完整 v4 套件，再執行

在 SmartAction_Taichi_Game_v4 資料夾的終端機執行：

若套件放在「下載項目」，也可以直接從任何目錄執行：

不需 chmod、不需手動 git add/commit/push。資料夾若被瀏覽器改名，請用實際名稱，或先輸入 bash 再將此檔從 Finder 拖進終端機，最後加 --fresh-login。

雙站腳本預設包含模型：先沿用有效的本地權重，缺少時下載與驗證，然後上傳兩站。開頭應看到 SmartAction dual uploader v4.0。若只想更新網站與照片、保留兩站已有權重：

03 · PERSONAL ACCESS TOKEN

兩個儲存庫都需要寫入權限

先登入 GitHub 的 kuonanhong 帳號。若 SmartAction 或 taichi 尚未建立，先到 建立儲存庫，選 Public。README 可有可無；腳本能初始化真正的空儲存庫，但不會替您建立 GitHub 儲存庫本身。

建立 fine-grained Token管理已有 Token

  1. GitHub 右上頭像 → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token。
  2. Token name 填 SmartAction-dual-upload，Expiration 選合適期限，例如 30 天。
  3. Resource owner 選 kuonanhong。
  4. Repository access 選 Only select repositories，同時選取 SmartAction 與 taichi。申請連結不會自動完成儲存庫選取。
  5. Repository permissions → Contents: Read and write；Metadata 保持 Read-only。本腳本不更改 Actions workflow，無須 Workflows 寫入。
  6. 按 Generate token，保存到密碼管理器。結果頁只顯示一次；Token 管理頁可管理權限，但不能重新顯示舊值。
  7. 執行一行上傳指令；Username 填 kuonanhong，Password 貼上 Token，再按 Enter。輸入不顯示字元是正常的；不要填 GitHub 帳號密碼。

--fresh-login 只在本次執行繞過舊憑證；不更改 Keychain 或全域 Git 設定。支援 Git credential-cache 的電腦會將這次認證保留在 RAM，讓兩站及各批次共用，結束後清除。它不會替 Token 增加權限。Token 若只授權一站，另一站仍會拒絕。

不要把 Token 寫入腳本、網站、Git URL 或對話。腳本由 Git 詢問密碼，不接收 Token 參數，不把 Token 存入專案。

04 · PAGES

Git 上傳完成後，兩站各自等待發布

看到 兩站 Git 檔案均已上傳並核對，代表兩個遠端分支 SHA 均已核對。它不代表兩個 Pages 部署已完成。

  1. 開 SmartAction Pages 設定 和 taichi Pages 設定。
  2. 採分支部署時，各選 Deploy from a branch → 腳本顯示的分支（通常 main）→ /(root) → Save。不要選 /docs。
  3. 若 SmartAction 原先有自訂 Actions 部署流程，保留原流程，確保部署產物包含 taichi/；本腳本不覆寫工作流程。
  4. 確認 SmartAction Actions 與 taichi Actions 最後一次 Pages 工作成功。
  5. 開 協會首頁，點 ☯ 入口進入遊戲；另可開 獨立太極網站。

倉庫程式碼網址 https://github.com/kuonanhong/SmartAction 與真正遊戲網址 https://kuonanhong.github.io/SmartAction/taichi/ 不同；首頁入口應開遊戲網站。

首次完整上傳可能觸發多次建置。腳本把網站按最多 96 MiB 分批，15 個模型分片仍以兩片／64 MiB 分成 8 批。約 150 MB 網站通常分 2 批，因此首次完整更新每站最多 2 + 8 = 10 次 push；沒有修改的批次會跳過。上傳前會印出實際規劃的網站／模型批次數。每個 Pages 網站的分支發布有每小時 10 次 build 的軟性限制；兩站分別計算。若網站超過兩批、該小時已經發布過其他更新，或短時間多次修改後重跑，仍可能碰到限額。自訂 Actions 發布不適用這一項每小時 10 次的限制，但本腳本不替您更改發布設定或工作流程。上傳成功後若建置限流，等限制解除，再於 Actions 重跑最後一次 Pages 工作；不必再上傳相同權重。

05 · ASSOCIATION HOME

只增加太極入口，保留協會首頁

腳本先取得遠端現有 SmartAction/index.html，再於最後的 </body> 前插入一個帶 ☯ 圖示的入口，連到 ./taichi/。原有 HTML、文字、圖片引用、導航和程式都保留。

入口以 SMARTACTION_TAICHI_LINK_START / SMARTACTION_TAICHI_LINK_END 標記。下次更新只替換這一段，不會重複出現按鈕。沒有根首頁或沒有可辨識的 body 結尾時會提醒並保留原樣，不會建立假的協會首頁；標記損壞或目標為符號連結則停止。

遊戲中的「回協會首頁」連到 SmartAction 首頁，兩個遊戲網址都可返回。此流程不刪除遠端其他檔案、不 force push。

06 · MODELS

權重放在遊戲內的 models/

相對於遊戲資料夾用途
models/manifest.json模型路徑、大小和 SHA-256，原套件已附
models/qwen3-0.6b-q4km.part01 … part15約 484 MB Qwen3 文字生成權重，每片最多 32 MiB
models/pose/pose_landmarker_lite.task人體姿態模型，保留既有檔案

原本的 SmartAction_Qwen3_CPU_Weights/ 可以放在 SmartAction_Taichi_Game_v4/ 旁邊。雙站腳本會將其 models/ 內驗證正確的分片合併到遊戲自己的 models/；缺少時才下載。也可以把完整 v2 或 v3 models/ 的分片複製到 v4 models/，但請保留 v4 的 manifest 與 pose 子資料夾。

單片和完整串接模型都會經過 SHA-256 驗證；兩片一批，最多 64 MiB。中斷後重跑相同指令，已成功且相同的檔案不會產生重複提交。第一站完成而第二站失敗時，重跑會先核對第一站再繼續第二站。

GitHub Pages 只提供檔案；Qwen3 生成在觀看者的 CPU / WebAssembly 執行。模型是文字教練，不是臉部或肢體動畫模型；人體偵測使用另外的姿態模型。模型已上傳不等於所有手機已實測推論成功。

核心 ZIP 不附大型 Qwen3 權重；下載器的固定來源和 15 片清單可重建它。首次安裝與上傳需預留數 GB 空間，因分片、Git 工作副本與儲存庫各會占空間。兩站各存一份權重。

腳本對本次網站與模型合計設定 950 MiB 的保守預檢、每個網站檔案 96 MiB 上限。Pages 發布內容上限 1 GB，遠端原有其他內容也會計入；SmartAction 若還有其他大型內容，請改用 --web-only，並透過遊戲的模型來源下載。預檢不會自動刪除遠端已存在的大檔案。

07 · RETRY

常見訊息與處理

訊息處理
403 / Permission denied確認 Token 未過期、兩個儲存庫都選取、Contents 可寫，使用 --fresh-login 重跑。受保護分支需依 GitHub 規則處理。
空儲存庫腳本核對確實沒有分支與標籤後，在副本建立 main；不必手動建立 README。
HTTP 400 / 連線中斷先核對遠端 SHA，收到同一提交就繼續；未確認最多重試三次，必要時採本次 HTTP/1.1 與128 MiB暫存。持續失敗請換穩定網路再重跑。
Everything up-to-date若前面有錯誤，這一行不能單獨視為成功。以腳本最後的遠端核對結果為準。
non-fast-forward / remote rejected明確拒絕不自動重試或強制覆寫。從最新遠端重跑；若有分支保護則先依規則處理。
模型校驗失敗雙站預設會修復；單站加 --with-model。不要修改 manifest hash 略過檢查。
404 / 網頁仍是舊版先確認最後一次 Pages Actions 成功、發佈分支和 /(root) 正確。再重新整理；必要時清除該站舊的離線快取。
找不到 .sh 或套件先解壓完整 ZIP，保留資料夾結構；使用實際路徑。下載檔若有 (1) 尾綴，請改回原檔名。

腳本只操作自己的暫存 Git 副本，不移動或刪除您的原始網站與模型。失敗會留下診斷副本路徑；提供錯誤文字時，請勿包含 Token。

ENGLISH

Deploy both sites from one project

bash Upload_Both_Sites.sh --fresh-login

Keep both upload scripts beside index.html and retain tools/. The dual uploader defaults to --with-model, validates/downloads the Qwen3 segments once locally, then updates kuonanhong/SmartAction under taichi/ and kuonanhong/taichi at its root. Use --web-only to preserve remote weights while updating the app.

A fine-grained token must select BOTH repositories and grant Contents: Read and write. Enter it only at Git's password prompt. With --fresh-login and supported Git credential-cache, both deployments share one temporary RAM credential cache, cleaned on exit; global credentials remain unchanged.

The existing association homepage receives one idempotent marked Taichi link. All bytes outside that insertion/replacement are preserved. No homepage is fabricated when the source is missing. Updates do not delete unrelated files or force-push. Interrupted operations compare remote commit IDs before bounded retries; rerunning resumes by comparison.

Configure each Pages site to publish the indicated branch from /(root), or retain the existing custom workflow and include taichi/. A confirmed Git upload is not a completed Pages build: wait for the latest Actions deployment on each repository. Website batches are at most 96 MiB; model batches remain at most two segments / 64 MiB. A roughly 150 MB app plus 15 model segments requires at most two app pushes and eight model pushes per site. The preflight prints the planned maximum; unchanged batches are skipped. Earlier builds in the same hour can still consume the per-site soft limit, so check the last Pages deployment. Existing other repository contents still count against Pages limits.
