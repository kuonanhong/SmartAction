  1. 下載新版 Upload_SmartAction.sh，覆蓋遊戲資料夾內、與 index.html 並排的舊檔。不要只執行外層另一份同名腳本。

02 · GITHUB PERSONAL ACCESS TOKEN

一步一步申請 Token

先登入 kuonanhong 帳號。GitHub 的 HTTPS Git 上傳以 Token 代替帳號密碼；一般模式可能使用既有的 Git Credential Manager、macOS Keychain 或已登入 GitHub CLI；本次排除 403 請加 --fresh-login，讓 Git 改用您這次輸入的 Token。

開啟 Token 申請表查看 / 管理 Token

  1. 可直接點上方申請連結。從 GitHub 介面進入的路徑是：右上頭像 → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token。
  2. Token name 填 SmartAction-upload；Expiration 可先選 30 天。到期後需重新申請或更新。
  3. Resource owner 選 kuonanhong。
  4. Repository access 選 Only select repositories，選取要上傳的 SmartAction；若也要發布短網址，先建立 taichi，再把 SmartAction 與 taichi 兩個儲存庫都加入。請勿漏掉這一步；申請連結不會替您選定儲存庫。
  5. Permissions → Repository permissions → Contents 設為 Read and write；Metadata 保持 Read-only。此上傳腳本不修改 GitHub Actions workflow，不需要為它勾選 Workflows 寫入。
  6. 按 Generate token，複製出現的完整 Token，保存到您使用的密碼管理器。離開結果畫面後，管理頁不能再次顯示原始 Token；忘記就重新產生。
  7. 執行上傳指令。若終端機問 Username，輸入 kuonanhong；問 Password 時貼上 Token，再按 Enter。貼上時通常不會顯示字元，這是正常行為。

Token 不要寫入 index.html、.sh、Git 遠端網址或對話訊息，也不要截圖公開。此腳本不讀取 Token 參數、不把 Token 存入專案。若已外洩，請在 Token 管理頁刪除它並重新申請。

「結果連結」是上方的 Token 管理頁；它會列出名稱、權限與有效期，並不是可公開分享的 Token 值。

03 · OPTIONAL CPU MODEL

一行完成：下載模型，再分批上傳

遊戲核心 ZIP 不包含約 484 MB 的 Qwen3 權重。要把模型也放到 GitHub 的 taichi/models/，執行：

bash "$HOME/Downloads/SmartAction_Taichi_Game_v2/Upload_SmartAction.sh" --with-model

它先檢查 Git 認證，再優先從同層的 SmartAction_Qwen3_CPU_Weights/models/ 合併有效分片；缺少部分才由固定版本來源下載。完成完整模型與每片 SHA-256 驗證後再上傳網站；接著將 15 個分片以每兩片一批提交、上傳與核對。每片最多 32 MiB，每批最多 64 MiB，共 8 批模型加 1 批網站。已完整存在的模型不會重新下載；中途 Git 上傳失敗，重跑同一行即可跳過遠端已有的相同分片。首次下載暫存與分片需要約 1.1 GB 空間，另需保留上傳副本的空間。

指令尾端實際行為
不加參數上傳網站；若本機 15 個權重分片已完整且驗證通過，也一併分批上傳。模型不存在時只上傳網站。分片不完整時停止，提示修復或用 --web-only。
--with-model優先合併旁邊已解壓的權重；缺少時下載或修復本機模型，再上傳網站及完整分片。
--web-only只更新網站，保留 GitHub 已存在的模型，不會刪除它們。

您截圖中的兩個資料夾要怎麼放？

保持 SmartAction_Taichi_Game_v2/ 與 SmartAction_Qwen3_CPU_Weights/ 在同一個外層資料夾即可。外層權重資料夾是安裝來源；網頁真正讀的是遊戲內的 models/。新版 --with-model 會自動合併有效分片，因此不必用 Finder 整個取代 models。

相對於遊戲資料夾的路徑用途
index.html網頁入口
models/manifest.json模型清單、大小與 SHA-256；原套件已附
models/qwen3-0.6b-q4km.part01 至 part15Qwen3 15 個模型分片，腳本複製或下載到這裡
models/pose/pose_landmarker_lite.task人體辨識模型，保留原有檔案

index.html 呼叫的 js/coach.js（已打包到 game.js）從網頁目前位置讀取 models/manifest.json，再讀取清單中的15片。因此 /taichi/ 對應 /taichi/models/；/SmartAction/taichi/ 對應 /SmartAction/taichi/models/。不會自動搜尋 SmartAction_Qwen3_CPU_Weights/ 這個外層名稱。

截圖只顯示資料夾名稱，無法確認遊戲內是否已有15片；腳本會實際檢查大小及 SHA-256。請不要刪除原有 models/manifest.json 或 models/pose/。GitHub 部署成功後，遊戲內還需按「載入已下載模型」，模型才會啟用。

Qwen3 是文字生成模型，不是臉部表情或身體動作模型。GitHub Pages 提供檔案下載；生成推論在觀看者裝置的 CPU / WebAssembly 執行。手機是否能載入、速度如何，仍取決於可用記憶體與瀏覽器，不能因模型檔案成功上傳就認定手機推論已測試成功。

也可以只上傳小型核心網站，讓使用者在遊戲的模型面板自行下載並快取 Qwen3；不必每次開站都下載。權重不使用 Git LFS，避免網頁載入到 LFS 指標文字而非模型內容。

完整模型尚未傳完時，網站可使用，但「載入已部署模型」可能失敗；請等 15 片全部成功。腳本將 15 片合併為 8 次模型 push，加上 1 次網站 push，首次完整上傳最多 9 次。GitHub 分支發佈有每小時 10 次 build 的軟性限制；若這一小時已有其他部署，仍可能碰到限額。若最後部署因頻率限制失敗，等待限制解除後，在 Actions 重新執行最後一次 Pages 工作；不要重複上傳相同模型。

04 · PUBLISH & VERIFY

上傳成功後，開啟真正的網站

新 taichi 儲存庫：開啟 taichi → Settings → Pages，選 Deploy from a branch、main（或腳本顯示的分支）、/(root)，按 Save。在 taichi Actions 確認最後一次 Pages 發布成功後，開啟 https://kuonanhong.github.io/taichi/。下面則是既有 SmartAction 站的設定。

腳本預設使用 https://github.com/kuonanhong/SmartAction.git 的預設分支，將這份遊戲放在 taichi/；根目錄原有協會首頁與其他檔案會保留。腳本不會強制推送、刪除遠端檔案，也不會自動改您的 Pages 設定。

  1. 終端機顯示「GitHub 檔案上傳已核對完成」與提交 SHA，代表 Git 遠端提交確認相同。只看到 Everything up-to-date 而前面有錯誤，不足以當成成功。
  2. 開啟 SmartAction → Settings → Pages。若既有網站採分支部署，確認 Deploy from a branch、分支與腳本最後顯示的分支相同（通常 main）、資料夾為 /(root)，按 Save。不要選 /docs，否則本方案的 taichi/ 不在發佈範圍。
  3. 若既有網站已使用自訂 GitHub Actions 部署，維持原流程，確認其部署產物包含 taichi/；單純推送檔案不會自動更改工作流程。
  4. 到 Actions 發佈紀錄，確認最新提交的 Pages build and deployment 成功。
  5. 開啟 https://kuonanhong.github.io/SmartAction/taichi/。這是預期部署路徑，不表示本套件交付時已替您發佈。實際網站仍需由您執行指令完成。

GitHub Pages 的確會讀取 index.html，但它透過 HTTPS 提供網頁與附屬檔案；直接雙擊本機 HTML 使用的是 file://。兩者的模組、相機、模型與離線快取權限不同。新版基本控制提供本機開檔入口，進階功能請使用套件啟動器提供的 localhost，或發佈後的 HTTPS 網址。

完整發佈不能只丟 index.html；JavaScript、樣式、照片、WASM、資料與模型清單也需同步。此腳本已按套件結構明列上傳項目。日後修改任一檔案，再跑同一行即會比較差異。

05 · TROUBLESHOOTING

遇到訊息時怎麼做？

訊息 / 情況處理方式
No such file or directoryZIP 要先解壓。確認資料夾實際名稱；可先輸入 bash （含空格），再把 Upload_SmartAction.sh 從 Finder 拖進終端機，按 Enter。
找不到完整套件腳本必須與遊戲的 index.html 放同一層，且保留 models/manifest.json 和所有子資料夾。
詢問提交者名稱 / Email這是 Git commit 作者資料，不是 Token。填自己的姓名與 GitHub 已驗證 Email，或 GitHub 帳號設定顯示的 noreply Email。只設定本次副本。
Authentication failed / 403確認帳號、Token 有效期、Resource owner、正確儲存庫（SmartAction 或 taichi）已選取，以及 Contents Read and write。加上 --fresh-login 繞過舊憑證，在終端機重新輸入新 Token。受保護分支可能要求 PR，本腳本不會繞過規則。
HTTP 400、連線中斷腳本已使用 HTTP/1.1 與小型模型批次；錯誤仍可能來自代理或網路。修正連線後重跑同一行。不要使用 git push --force，也不要因最後一句 up-to-date 忽略前面的失敗。
non-fast-forward / 遠端 SHA 不同代表上傳期間可能有另一人更新遠端。重跑腳本會從最新版本重新比對；若持續發生，先協調避免同時編輯相同檔案。
模型 SHA-256 錯誤使用 --with-model 重新下載與驗證；不要改清單裡的 hash 來略過驗證。也可以先 --web-only 更新遊戲。
網頁還是舊版 / 404檢查最新 Actions 是否成功、分支與 /(root) 是否一致。成功後重新整理；若離線快取仍舊，可在瀏覽器該站的網站資料設定清除快取，再開 HTTPS 遊戲網址。

GitHub 普通 Git 不接受大於 100 MiB 的單一檔案；本模型以最多 32 MiB 分片。分片仍會計入儲存庫與 Pages 的整體大小；Published Pages 上限 1 GB。若儲存庫還放了其他大型模型，請改採遊戲中的來源下載功能，保持網站核心小型化。
